> **本 Fork 的改动（2026-09，适配游戏 r150 / Unity 6.3）**
> 1. **游戏接口兼容**：`scrPlayer.Hit(bool)` → `Hit(long?, bool)`；`scrMisc.GetAdjustedAngleBoundaryInDeg` 首参改 `Difficulty` 且返回结构体（判定探针改用 `.Counted`，并在 Prefix 捕获原始角度）；`scrHitErrorMeter.AddHit` 新增 `HitMargin` 参数且会原地改写 `angleDiff`；`CountValidKeysPressed` 按键过滤改为 Transpiler（保留游戏新增的触屏/合作/键位限制器逻辑）；替换当前编译器不支持的 `[with(n)]` 语法
> 2. **手法模拟算法重写**：分片量化为**实际音符间隔**的整数倍（片长 = 音符间隔 × 本手音数），切点按“距离（欠长加倍）− 间隙”综合评分吸附事件边界（不拆双押/和弦、不把可合并的连打簇提前换手）；逐层 `floor.speed` 局部速率取“下一事件”所属层（修复 SetSpeed 提速后片长失配、被切成 3-1-1 碎块的问题）；换手仅在**实际音符速率**（按事件间隔折算，音符/分钟；90° 砖是砖 BPM 的 2 倍）超过阈值时发生，未超阈值切回并保持起始手（主手）连续敲击（低 KPS 段单指连打）；超阈值段按“单指上限 = 阈值”分配手指总数 n = ceil(音符速率/阈值)（120→1、240→2、360→3、480→4…），n 为奇数时主手多一指（三指 = 主手 2 音 + 副手 1 音交替），片内事件数超过单手按键数时取满全部按键（极高 BPM 不再只用部分按键）；空片不再切换手；段边界仅在键位配置变化时重置（修复起始手连按两次）；按住时长**跟随实际音符间隔 × 时长比例**（平滑单调），上限 = 本片音符跨度 + 最小内部间隔（片尾跨暂停不一直按住），并新增“按键时长使用旧版算法（1.3.0.30）”开关，可在旧版折叠短按与新版跟随间隔之间切换
> 3. **原生层**：新增 `BuildTechniqueHitEventsEx` 导出（旧导出保留兼容）；`InputSystem` / `TechniqueSimulator` 以 Release|x64 重建（工具集 v143）
> 4. **按键显示**：小键盘 `N0–N9 / N* N+ N- N. N/`、功能键、方向键等标签，长标签自适应框宽，未知键回退 `0xXX`
> 5. **设置持久化**：变速容差即时写入当前配置档（修复重启归零）
> 6. **分片基准修复**：分片基础时长改为跟随**实际音符间隔**（跳过同刻双押/和弦后到下一音符的时间差）× `round(音符速率/(2·阈值))`，取代“局部半拍量化”。非 90° 砖 / SetSpeed 混排谱面（如雪花样式 + 双押）中，局部半拍的整数倍与实际音符间隔不整除时，量化片长会跨过下一个音符，把单音与紧跟的双押/和弦并到同一只手，造成换手相位漂移（表现为 `R2 L1 R1 L3…`）；修复后恢复稳定的 `R2 L1 R1 L1` 交替。对 90° 砖（间隔=局部半拍）与旧公式完全一致
> 7. **按压时长基准修复**：仿人下限由局部地板 BPM（`bpm×floor.speed`）改为**实际音符间隔**折算（`GetNoteFoldedPressLength`），并新增同刻判定容差。匀速谱面（如雪花谱）此前因 `SetSpeed` 让各砖 speed 不同，按住时长在 39~73ms 间忽长忽短、同一双押两键甚至相差十几毫秒；修复后匀速段各音符（含同刻双押/和弦）时长一致
> 8. **多押按键均分**：新增设置开关。用**自适应多押簇**识别同一时刻（内部间隔 ≤12ms 且整簇跨度 ≤35ms，覆盖"多块 1° 砖 + 999 midspin"这类常见八押，整簇 5~22ms；真正的匀速连打不会被误判）；按键数超过单手按键数时，开=对半均分到两只手（6押→R3 L3、7押→R4 L3、8押→R4 L4，单数多的一键给主手），关=主手取满后余数给另一手（6押→R5 L1）
> 9. **判定误差自动校准方向修正**：r150 的判定探针 `errMs<0 = 迟发`（复刻游戏 `AddHit` 的 `*−57.29578`），而旧闭环把迟发当早发继续加大偏移，形成正反馈——密集多押图（如十六押）上偏移被推到 +60ms 钳制位、系统性迟发而“打不过”。改为负反馈（`_autoOffsetMs += step`）后收敛到取消迟发的偏移
> 10. **文档**：README 与中英文本地化文案同步更新
> 11. **手指数分配与按压时长修复（2026-09-21）**：修复“>240 仍用双指、到 390 才升四指”与“>240 后按住时长突变”两个问题：
>     - 手指总数由 `round(速率/(2·阈值))` 改为 `ceil(速率/阈值)`。旧公式只能得到偶数只手指数（每片每手 k 音、两手对称），240~360 一直是双指（每指 120~180 次/分、超过单指上限），且半整数边界受浮点误差影响：360BPM 实测速率 359.99999，`round(1.49999996)=1` → 360 段仍双指、390 段才升四指；新公式 240→双指、360→三指、480→四指…，n 为奇数时主手多一指（三指 = 主手 2 音 + 副手 1 音交替），每根手指的敲击频率都不超过阈值；
>     - 按住时长不再按片结构推算（`CalculateReleaseTime` 的“到下一片结束的一半”：片长随速率阶跃为 2k×间隔，240BPM 按 150ms、刚过 240 就跳到 267ms，并随 k 变化反复锯动），改为**直接跟随该音的实际音符间隔 × 时长比例**：测试图 120→900BPM 全程 300→240→200→171→150→133→120→109→100→92→86→80→75→…（720BPM 起由 50ms 拟人下限托底）平滑单调，与 240 以下同一占空比；
>     - 折叠仿人下限只在未超阈值（速率 ≤ 阈值）时生效，超阈值段不再把基准折回一个八度；
>     - 密簇（相邻间隔 ≤12ms 的多押/偏移双押）的按压基准退到簇外正常间隔，避免按住时长被压缩到 2~4ms（不足一帧，帧采样输入链路可能丢键）。
> 12. **快速双押/多押按住时长修复（2026-09-21 二次）**：修第 11 条后暴露出双押/多押时长过短：
>     - `cap`（本片跨度 + 最小内部间隔）此前只跳过同刻（≤3ms）的间隙。八押簇内相邻 3.2ms 的间隔被当成“有意义的内部间隔”，`cap = ratio×(簇跨度+3.2ms)` 只有十几毫秒，前半段八押按住被截到 15ms（后半段 0.8ms 间距因 ≤3ms 被同刻跳过、反而正常）——现改为跳过 ≤12ms 的**簇内**间隙，整簇统一退到簇外正常间隔；
>     - 间隔十几~几十毫秒的双押/快速连打（如 16.7ms、33.3ms）不满足密簇条件，按住 = 0.6×间隔 只有 10~20ms，观影/输入上都太短——新增**拟人最短按压 50ms**（真人点按约 40~60ms，且跨过至少一帧）：按住时长 = max(实际间隔×比例, 50ms)。慢速段（>83ms 间隔）不受影响，高频段（750BPM 以上）稳定在 50ms。
> 13. **双押/高密度 Timing 迟发修复（2026-09-21 三次）**：双押及以上、BPM 越高越明显时，游戏判定会比实际偏高 5~10ms（十六押测试、多押测试2、20000高速铺等）。根因**不是性能**：同一时刻的多个按键在宏工作线程里**逐个 SendKey**，每次 Send（虚拟直喂 + 镜像 `SendInput`）耗时 0.1~2ms，排在后面的键实际发送时刻已晚于理想；而虚拟事件的时间戳取“发送瞬间”，游戏按事件时间戳亚帧判定 → 后面的键被判成迟发（八押可累积到 5~10ms）。修复采用**事件时间戳批锚定**：以**批首事件的真实发送时刻**为基准（宏已等到其理想时刻才发，误差仅调度抖动），批内其余事件按各自的**理想歌曲时间差**折算真实秒排上去（批窗口 50ms，超出重新锚定）——既消除双押/八押逐个发送的累积延迟，又**不依赖 `audioNow` 的绝对外推**，高密度连打段（如 20000 高速铺）不会因外推累积误差越走越偏。若仍偶有偏差，可关闭 **镜像同步按键**（每次虚拟键额外 `SendInput` 是延迟的主要来源；宏内置按键显示不受影响，外部 `Input.GetKeyDown` 显示器会看不到）。

**ADOFAIMacro** 是《A Dance of Fire and Ice》(ADOFAI) 的 UnityModManager 模组：解析谱面地板时间戳，由独立高优先级线程微秒级定时发送按键。从"直接判定触发"到"系统级按键模拟"再到"左右手手法模拟"，覆盖纯自动过谱到拟真手法的各种场景。

> ⚠️ **两条红线，先说清楚：**
> - **不要修改 `Info.json`** —— 模组带防篡改检测，改动后启用时会直接退出游戏。
> - **与 BaseMacro 不兼容** —— 检测到会直接退出游戏。

## 功能一览

- **自动触发**：谱面时间戳 → 高精度定时按键；双缓冲时间锚点同步主线程与工作线程，无锁零等待。
- **四种输入路径**：直接判定 / SendInput / SkyHook 底层注入（NtInject / NtSendInput）/ 虚拟异步键盘直喂（跳过系统注入，亚微秒抖动）。
- **手法模拟**：左右手交替、BPM 阈值自动细分时间片（单手多指连打）、可配置按键 / 顺序 / 按压时长、变速分段覆盖、每关独立配置；核心算法在 C++ 原生 DLL 中运行。
- **时间微调**：±100 ms 偏移，游戏内方向键实时调节；判定误差自动校准（闭环，自动消除变速段偏移）。
- **按键过滤**：黑 / 白名单，同步（KeyCode）与异步（VK 码）独立过滤。
- **其他**：死亡后自动按键、游玩期 GC 停顿抑制、窗口失焦拦截、中英双语 UI。

## 快速上手

**前置**：已安装 ADOFAI 和 [UnityModManager](https://www.nexusmods.com/site/mods/21)（≥ 0.27.0）。

1. 从 [Releases](https://github.com/adofaiex/ADOFAIMacro/releases) 下载压缩包，用 UMM 安装；或手动解压到游戏的 `Mods/ADOFAIMacro/` 目录。
   - 目录内应包含：`ADOFAIMacro.dll`、`InputSystem.dll`、`TechniqueSimulator.dll`、`Localization/`（zh-CN / en-US）。
2. 启动游戏，打开 UMM 模组窗口，启用 **ADOFAIMacro**。
3. 「宏」选项卡 → 勾选 **启用宏**。
4. 默认配置（按键模拟关闭 = 直接判定）即可自动过谱；判定整体偏早/偏晚时，到「延迟设置」调整 **延迟 (ms)**，或游戏内按 <kbd>←</kbd>/<kbd>→</kbd> 微调。

就这么多。更多玩法往下看。

## 触发模式与输入链路

「按键设置」中的三个开关组合出四条链路，按需选择：

| 你想要什么 | 配置 |
|---|---|
| 只要能过谱，链路最短 | 按键模拟 **关** |
| 需要真实系统按键（连打观感、按键音效、第三方工具读键盘） | 按键模拟 **开** + 使用高级输入 **关**（走 SendInput） |
| 高频谱面 / 多软件并行 / SendInput 被拦截 | 按键模拟 **开** + 使用高级输入 **开** + 输入模式 **自动** |
| 极致同步精度 | 上一行配置 + **虚拟异步键盘直喂** 开（默认已开） |

各链路说明：

1. **直接判定**（`SimulateKeyPress = false`）：工作线程计数 → 主线程调用游戏 `Hit()`。零系统副作用、延迟最可控，但游戏将其视为自动命中，不产生真实按键。
2. **SendInput**：标准 Win32 注入，兼容性最好。
3. **SkyHook 高级输入**：通过 `InputSystem.dll` 走更底层路径。输入模式四选一：
   - **自动**：优先选择可用的最底层方式（建议从这里开始）；
   - **NtInject**：最底层，直接注入原始输入流；
   - **NtSendInput ★**：内核边界注入；
   - **SendInput**：同标准 Win32。
4. **虚拟异步键盘直喂**：合成按键事件直接送进游戏自身的输入队列（与真实键盘钩子同一入口），跳过整个系统注入链路，时间戳本地生成、亚微秒抖动，且无窗口焦点依赖。不可用（如按键无映射、布局校验失败）时**自动回退**注入路径，无需手动干预。

## 设置速查

按 UMM 面板的选项卡组织。「内部名」对应配置文件中的字段。

### 宏

| 面板项 | 内部名 | 默认 | 说明 |
|---|---|---|---|
| 启用宏 | `Macro` | 关 | 宏总开关。 |

### 按键设置

| 面板项 | 内部名 | 默认 | 说明 |
|---|---|---|---|
| 按键序列 (逗号分隔) | `MacroKeys` | `D,F,J,K` | 简单轮转模式的按键序列。 |
| 按键模拟 | `SimulateKeyPress` | 关 | 关 = 直接判定；开 = 系统按键模拟。 |
| 使用高级输入 | `SkyHookMode` | 关 | 开启后走 SkyHook 路径，否则 SendInput。 |
| 虚拟异步键盘直喂 | `UseVirtualAsyncInput` | 开 | 见上文链路 4；不可用自动回退。 |
| 虚拟按键同步系统输入 | `MirrorVirtualKeys` | 开 | 直喂成功后同步注入一份真实按键，让按键显示器等第三方工具看见虚拟按键；注入回声自动丢弃，不会双判定。 |
| Win API 输入模式 | `InputMode` | 自动 | 自动 / NtInject / NtSendInput ★ / SendInput。 |

| 面板项 | 内部名 | 默认 | 说明 |

### 按键书写格式（通用）

- 多个按键用英文逗号分隔，如 `J,K,L`。

## 手法模拟指南

开启后（需同时开启 **按键模拟**），宏不再简单轮转按键序列，而是模拟真人双手打谱：时间按"片"划分，每片交给一只手；**只有实际音符速率超过速度阈值时才会左右交替**，未超阈值时切回并保持**起始手（主手）**连续敲击（片内 1 个事件即单指连打，多个事件由该手多指滚动），因此快段后进入慢段会自动回到主手。实际速率按音符间隔折算（音符/分钟），注意 90° 砖一块 = 半拍，其实际速率是砖 BPM 的 **2 倍**（45° 砖 4 倍、直线砖 1 倍），SetSpeed 变速同样按间隔体现。片长以**实际音符间隔**为基准（跳过同刻双押/和弦后到下一个音符的时间差，天然涵盖 SetSpeed 与各种砖角）：不超过 **速度阈值** 时每音一片、该手单指连打；超过时按"**单指敲击上限 = 阈值**"分配手指总数 `n = ceil(音符速率/阈值)`（如阈值 120：240BPM→2 指、360→3 指、480→4 指、600→5 指…），每片由一只手负责 `n` 个音中的一半——`n` 为偶数时两手各 `n/2` 个音交替，`n` 为奇数时主手多一指（三指 = 主手连敲 2 音、副手 1 音，如此交替），保证每根手指的敲击频率都不超过阈值；片内事件数超过该手按键数时直接取满全部按键。切点始终落在音符网格上（评分吸附事件间隙），非 90° 砖（如雪花谱的混角度/变速组合）不会因半拍量化跨过下一个音符、把单音与双押并到同一只手。按住时长 = max(**该音的实际音符间隔 × 所设"左/右手时长"比例**, 50ms)（随速率平滑单调，如 240BPM→150ms、360BPM→100ms、720BPM 以上稳定在 50ms；密簇内退到簇外间隔、同刻双押/和弦共享同一基准，且从不短于一帧，避免帧采样输入链路丢键），并以"本片音符跨度 + 最小内部间隔（跳过 ≤12ms 的簇内间隙）"为上限（片尾跨暂停/长空拍不会把整段按住）。多押（同一时刻按键数超过单手按键数）默认由主手取满、余数交给另一手（如 6 押→R5 L1）；开启 **多押按键均分** 后改为对半均分到两只手（6 押→R3 L3、7 押→R4 L3、8 押→R4 L4，单数多的一键给主手）。这里对"同一时刻"做**自适应识别**：相邻事件间隔 ≤12ms 且整簇跨度 ≤35ms 视为一次多押（覆盖"多块 1° 砖 + 999 midspin"这类常见八押，整簇约 5~22ms；真正的匀速连打不会被误判）。分片切点自动吸附到事件间隙（连打簇的自然分界），不会把快双押/和弦拆到两只手，也不会把可合并的连打簇提前换手。

### 基本参数

| 面板项 | 默认 | 说明 |
|---|---|---|
| 启用手法模拟（左右手交替） | 关 | 总开关（需按键模拟）。 |
| 起始手 | 右手 | 第一个时间片交给哪只手。 |
| 全局·速度阈值 (BPM) | 500 | 单指敲击上限（范围 50 ~ 2000，单位=音符/分钟）：实际音符速率不超过该值时切回起始手（主手）敲击，超过才左右交替，并按 `n = ceil(速率/阈值)` 分配手指总数（240→双指、360→三指、480→四指…，奇数指时主手多一指）。90° 砖实际速率 = 砖 BPM×2。 |
| 左/右手按键 | `D,F` / `J,K` | 每只手可用的键，内置预设 DF/JK、DS/JK、ASDF/JKL。 |
| 左/右手顺序 | 空 | 见下方格式说明，留空 = 默认轮转。 |
| 左/右手时长 | `0.8,0.8` | 按压时长比例（0 ~ 1）。按住时长 = max(该音的实际音符间隔 × 比例, 50ms)（随速率平滑单调、同刻双押/和弦等长，且不短于一帧）；上限为“本片音符跨度 + 最小内部间隔（跳过 ≤12ms 的簇内间隙）”（片尾跨暂停不拖长）。长按（hold）谱面自动处理。 |
| 按键时长使用旧版算法 | 关 | 开：按压时长按 1.3.0.30 的八度折叠片长（阈值附近的一次短按，慢谱不会长按到下一个音符）；关：跟随当前片长（按到接近下一音符）。 |
| 多押按键均分 | 关 | 同一时刻按键数超过单手按键数时：开=对半均分到两只手（6押→R3 L3、7押→R4 L3、8押→R4 L4，单数多的一键给主手）；关=主手先取满全部按键，余数交给另一手（6押→R5 L1）。 |
| 变速容差 | 0 | 时间片切点对齐事件间隙的强度。0 = 按拍簇分组，越大越倾向合并为更长的单手连打；应对连续微变速谱面。 |

**按键顺序格式**：用 `|` 分隔不同按键数的片，逗号分隔 1-based 键序号。例如 `1,2 | 1,2 | 1,2,1`：单键片按第 1、2 键轮转，三键片按 1→2→1。留空 = 默认顺序。

### 配置（Profiles）

可保存多套完整手法参数（按键、顺序、时长、起始手、变速容差、分段），面板上一键新建 / 删除 / 切换。

每张图可以保存独立配置：

- 文件与关卡同目录，命名 `关卡名.adofaimacro.json`；

适合给高 BPM 段落配更小的按键组合、为特定手癖设计键序、按图精调参数。

## 常见问题

**Q1：宏开了但没反应**
按顺序检查：UMM 中模组已启用 → 启用宏已勾选 → 按键序列格式正确（英文逗号分隔）→ 若开了"窗口未激活时阻止按键输入"，切出游戏时按键会被拦截（回到前台即恢复）。

**Q2：时准时不准、偶尔漏键**
先用方向键微调延迟（每次 1 ms）；高频谱面开高级输入 + 输入模式自动；高密度图开"游玩期抑制GC停顿"；仍冲突就开按键过滤隔离干扰源。

**Q3：变速谱面偏移大**
确认"判定误差自动校准"开启（默认开）；手法模拟下可调高"变速容差"，或用分段给变速段单独设 BPM 阈值。

**Q4：死亡后自动按键不生效**
仅高级输入（SkyHook）模式生效 → 确认已开启；确认死亡按键已启用、键名 / 键码有效；必要时增大延迟秒数。

**Q5：按键显示器看不到宏按键**
虚拟异步键盘直喂不经过系统输入流，第三方工具读不到 → 开启"虚拟按键同步系统输入"（默认开）。

**Q6：按键过滤"没有作用"**
确认过滤已启用；确认模式（黑 / 白名单）与预期一致；高级输入场景下别忘了设置**异步**按键列表。

**Q7：启用模组后游戏直接退出**
`Info.json` 被修改过（防篡改检测），还原它；或装了 BaseMacro（互斥），卸载之。

**Q8：手法模拟没输出 / 提示 DLL 不可用**
把 `TechniqueSimulator.dll` 放到 `Mods/ADOFAIMacro/` 目录；Release 版缺 DLL 时手法模拟无事件输出。

**Q9：刚进游戏判定飘 / 需要死亡一次？**
是。首次进入需要死亡一次完成时间校准，之后正常。

提 issue 时建议附上：游戏版本、模组版本、关键配置截图、是否使用 SkyHook 及当前输入模式、复现步骤与日志。
