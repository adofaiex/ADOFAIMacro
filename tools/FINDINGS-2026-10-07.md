## 三、复现参照输出的关键坑（务必遵守）

`main.exe` 生成 speeddata 时，第二个字段的**符号**决定「重启语义」：

- `=bpm,=1` → `restart[1]=1`，**强制指定主副手**；
- `=bpm,*1` → 只 `restart[0]=1`（重算时间片，**不**强制手）。

**若每砖都写 `=bpm,=1`，手会被强制成同一只、换手被掐死**，产出退化解（如只用 2 键、单键 40/s）。
正确写法：首行 `=bpm,=1`，之后只在 BPM 变化处写 `*,1`。用户自己的 `main.speeddata` / `level.speeddata` 即此模式。

> 我第一版生成的 `game.speeddata` 犯了此错（3307 行全是 `=bpm,=1`），
> 产出「只用 2 键 / 单键 40/s」的退化解，一度误导了判断。已用正确版本重跑。

1. 时间片划分 → 每片**整片归一只手**，片与片之间交替；
2. 片内含 `cnt` 个音时，用该手的按键顺序表第 `cnt` 项取键 → **同一只手内多个不同键**。

这正是 `main.cpp` 的 `turn_to()`：
`keys_list[hand][ keys[hand][piece[0]-1][i] ]` —— 用**片的音数**索引 order 表。

mod 侧的 `oi = min(evCount-1, keyCount-1)` 是同一语义。所以差异**不在取键逻辑**，
而在**时间片边界**。我此前的「片长对齐到每片 1 音」把 `cnt` 恒钉成 1
→ `oi` 恒为 0 → 每手永远只取 order 表第一项 → 退化成单键。
**这就是「只用 2 键」的完整因果链。**

## 六、下一步（若用户实测后仍不满意）

1. **主线：对齐时间片划分**，不是对齐片长。
   已有 `tools/abverify/ref_pieces.txt` / `dll_pieces.txt` 是逐片对拍产物
   （格式 `P <序号> cnt=<音数> hand=<0/1> len=<片长> start/end/evStart/mult`），
   是首选工装：直接看第几片开始分歧、分歧片的 `cnt` 差多少。
2. **保留多键分摊**：`cnt` 必须能大于 1，否则键数会塌。
3. **验收用 `RefAgree`**：逐音一致率 / 最长连击 / 换手率 / 键数，四项对照参照。
   **不再**用自创的同帧指标。
4. 局部验证 2.1 的「状态残留」假设：定位三连音段之后的伪双押，
   看是否为手性相位或倍乘器 `mult` 的跨片残留。
